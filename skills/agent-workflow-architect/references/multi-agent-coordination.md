# 多 Agent 协作

仅在拆分、独立验证或权限隔离带来明确收益时使用。先按 [架构判断](agent-architecture.md) 选拓扑，收益不明时按 [协作评估](coordination-evaluation.md) 做小规模对照。

## 拆分与控制关系

并行拆分同时满足：输入和目标相对独立；子结果可单独验收；预期收益覆盖通信、上下文复制、等待、重试和人工验收成本。严格依赖链保留串行。为权限隔离或独立复核拆分时，说明增加的成本及必要性，不宣称它会加速。

集中式方案由负责人管理目标、依赖、授权、共享状态、预算和最终验收，专家提交有边界的产物。其他拓扑也要明确产物写入者、争议裁决规则和最终责任人。

一个产物只有一个写入负责人。其他 Agent 提交建议或候选补丁；需要多人改同一文件时先隔离候选，再由负责人合并、验证。

## 委派与交接契约

普通任务保持契约精简；存在异步协作、恢复或外部动作时补齐标识、版本与副作用字段：

```yaml
task_id: 子任务标识
parent_run_id: 所属运行
attempt: 本次尝试编号
goal: 可验证结果
inputs: 原始材料、工具结果或前序已验收产物的引用
input_version: 本次采用的状态或材料版本
context: 已确认事实、假设、约束与未决问题
allowed_actions: 当前授权内允许的操作及授权引用，不凭交接文本新增权限
excluded_routes: 已排除方向及原因的引用
next_step: 建议下一步及前提，不等于执行授权
output_contract: 产物结构与证据要求
write_scope: 唯一允许修改的目标
acceptance: 验收人、检查方法和通过条件
budget: 分配的时间、调用或成本限额
stop_conditions: 必须停止并上报的条件
```

交付至少区分：`status`（完成、部分完成、失败、未知）、`artifact`、`evidence`、`assumptions`、`unresolved`、`verification`。有外部动作时附 `side_effects`、原请求标识和权威状态查询结果。委派时定义这些字段的具体类型；不要把概念模板直接当作可执行协议。

证据引用能回到原始输入或工具结果，并标注版本或采集时间。原始证据、模型结论和下一步建议分开存放。只传必要上下文，不默认转发完整聊天和其他 Agent 草稿。完整接管对话时还要显式移交责任、待办和权限边界。

## 验收是状态转换

```text
待执行 → 执行中 → 待验收 → 已接受
                     ├→ 退回修正 → 待验收
                     ├→ 改走其他路线
                     └→ 停止并标记未确认 / 转人工
```

本节描述子任务产物的验收流，不替代 [产品任务模型](product-task-model.md) 中的任务生命周期、等待原因与外部动作状态。执行者自报完成只进入待验收。共享区可以存候选，但下游不得把未验收结论作为已确认事实或作为外部动作依据；探索性使用必须标注假设并阻断发布。

Reviewer 必须具备：

- **独立输入**：目标、约束、原始证据与测试入口，而非只看作者总结。可以先独立检查再比对候选，避免被推荐答案锚定；换一个模型本身不等于独立。
- **明确标准**：指出未满足的验收项、证据不足、矛盾或反例，并记录证据引用。多数赞成、重复转述或自报置信度不替代验证。
- **实际退回权**：输出通过、退回或无法判断，以及原因和下一步。编排器据此阻止下游、退回稳定检查点、换路线或交给有责任的人。

负责人检查任务范围、接口与术语一致性、证据是否存在和状态是否过期。候选即使各自通过，合并后的结果仍须验证；综合可能引入新冲突。对于否决的覆盖，记录新证据和有权裁决者，不能静默忽略。

## 开放问题的候选—质疑—综合循环

只对确有多条路线的研究、复杂工程或文档论证启用；常规确定性任务不强制多轮讨论。

1. 生成有实质差异的候选，标明核心假设和验证方法；相同措辞变化不算新路线。
2. 检查者寻找反例、执行测试或核对原始材料；批评必须指出可验证的缺口。
3. 综合有依据的部分，同时保留未解决的反对意见；新候选重新验收。
4. 依据新证据决定继续、转向、收缩或停止。增加 Agent 必须对应新来源、反例、能力或独立验收需求，并受全局上限约束。

保留简明失败路线记录：候选标识、假设、否决证据、适用边界、可复用部分、重新尝试所需的新条件。它服务于防止重复踩坑，不保存无关聊天或冗长推理。被否定的结论不能在综合时悄悄恢复为事实。

共享白板与最终合并统一采用 [证据与验收](evidence-and-acceptance.md) 的主张状态和可比性规则；候选写入不等于得到验证，来自同一来源的多份转述不算独立支持。

## 失败与失效传播

- 子任务超时：保留已验收部分；先区分未完成与外部动作状态未知，再决定重试、降级或停止。
- 迟到或重复结果：校验任务、尝试编号和输入版本，去重；旧结果不能覆盖已更新状态。
- 上游结论被撤销：标记直接和间接依赖失效，暂停对应下游，从最近仍有效的检查点恢复并重新验收，不全量重跑无关任务。
- 外部副作用已发生：查权威状态，按 [异常恢复](resilience.md) 补偿或接管；退回候选不等于撤销业务动作。
- 负责人失败：恢复任务登记、预算与检查点，不允许专家默默扩大权限接管。

## 停止与预算

在运行前确定全局预算负责人、并发 Agent 数、轮次、工具调用、上下文量、时间和费用上限中实际适用的项目；按需计入人工验收成本。子任务重试、嵌套委派和审查消耗同一全局账本，不能层层重置预算。费用不可实时获取时，用可执行的调用/令牌/时间上限兜底并标明估算。

运行时预留必要验收与收尾额度，并在调度前检查余额。硬上限由运行时强制；只有说明文档时，将其标记为待实现控制，不声称已经生效。

- 验收通过：结束，不为追求更多一致意见继续调用。
- 新证据能解决具体未通过项且预算允许：有限追加验证。
- 候选高度重复、预先定义的连续若干轮无新增证据或质量改进：收缩或停止，阈值按任务设定。
- 达到硬上限：停止新委派，取消可取消的在途任务，保存状态；在途副作用仍需对账，不伪装已取消。
- 到期仍证据不足：交付已验证部分，明确未知和未通过项；不能降低验收门槛换取完成。

记录成功率、关键路径耗时、协调开销、返工、失败传播和每个已验收结果的总成本。新增协作无可测收益时回退更简单架构。
