# Agent 架构审查

审查目标是找到最可能让系统在真实环境中产生错误行为的机制，并用代码、配置、测试、日志或运行轨迹支持结论。

## 审查输入

优先收集：

- 业务目标、风险承受范围和发布对象。
- Agent 入口、Prompt 组装、工具定义和执行路径。
- 状态、会话历史、长期记忆和恢复机制。
- 权限、审批、模型与供应商配置。
- 真实或代表性运行轨迹、错误日志和测试结果。

没有证据时明确标记“尚未验证”，不要仅凭架构图宣布安全或可上线。

## 核心审查面

### 1. 业务与边界

- 成功是否定义成真实业务结果，而不是模型返回文本？
- Agent 是否承担了应由代码或真人负责的确定性、高风险决策？
- 业务例外、取消和人工责任是否明确？

### 产品机制与用户控制（长流程或产品设计时）

- 生命周期、等待原因、产物验收和外部动作状态是否分开，界面与后台是否一致？
- 用户改目标、补材料或否决结论后，是否更新版本并使受影响下游失效？
- 暂停、取消、重试和补偿按钮是否有后端条件；未知副作用是否误报失败？
- 是否明确关闭页面的运行语义，人工接管时是否阻止旧执行者继续写入？
- 事实、候选、决定与授权是否混淆；关键结论能否追溯到对应版本的原始证据？
- 合并结果是否对齐对象、口径与时间；用户认可是否被错误当作事实验证？
- 具体行动确认是否可审阅、与版本绑定；过期或撤销的授权是否仍能执行？

### 2. 指令与上下文

- 系统指令是否冲突、过长或重复注入？
- 同一信息是否同时出现在 Prompt、历史、记忆和摘要中？
- 用户修正能否覆盖过期记忆？
- 交接是否无差别传递完整历史和工具噪声？

### 3. 工具纪律

- “必须调用工具”是否只存在于 Prompt，而代码允许跳过？
- 每次高风险工具调用是否校验输入、有效授权及适用审批要求，并重新检查目标状态？
- 工具返回是否经过结构和业务状态校验？
- 超时、部分成功和重复调用是否可能造成副作用？

### 4. 多 Agent 协作

- 拓扑是否匹配任务依赖？每项产物、争议和最终结果是否有明确负责人或裁决规则？
- 多个 Agent 是否能同时写同一状态或文件？
- 委派是否有输入、输出、边界和验收契约？
- 是否存在无限讨论、循环交接或无人裁决的分歧？
- Reviewer 能否访问原始证据，并让未通过结果真正退回或阻断下游？
- 聚合是否掩盖共同错误来源或丢失反对意见？综合产物是否重新验收？
- 上游失效与迟到结果能否被识别，相关下游是否暂停并重新验证？
- 全局预算是否覆盖嵌套委派、重试和审查，运行时能否强制停止？
- 是否有基线、协调成本和回退条件的证据？未做对照时是否明确标记？

### 5. 状态与记忆

- 权威业务状态在哪里，谁能修改？
- 会话内容是否被误当成长期事实？
- 记忆是否有来源、准入、修正、过期和删除规则？
- 中断恢复是否依赖检查点和权威状态，而不是重放聊天？

### 6. 隐藏执行层

- 主 Agent 之外是否有静默总结、修复、重试或二次改写模型？
- 最终展示内容是否与内部结果一致？
- 错误是否被捕获后丢弃，导致假成功？
- 缓存或旧运行产物是否被当作实时证据？

### 7. 可观测性与运营

- 一次运行能否串起模型、工具、交接、审批、错误和最终业务结果？
- 日志是否足以恢复和追责，同时避免敏感数据泄露？
- 是否有失败队列、成本阈值、告警负责人、降级和快速停用方式？

## 证据驱动的发现

每条发现包含：

```yaml
severity: 阻断 | 严重 | 重要 | 建议
title: 简短问题名
symptom: 用户或运营看到什么
mechanism: 问题怎样发生
root_cause: 最深层原因
evidence: 文件行号、配置、测试或轨迹引用
confidence: 高 | 中 | 低
recommended_fix: 最小可靠修正
verification: 如何证明修复有效
```

按严重度排序，不要先写表扬或泛泛总结。如果当前状态看起来正常，但历史事故证据显示问题曾发生，不能用当前状态抹掉事故。

## 常见阻断模式

- 模型可直接执行资金、删除、外发或提权，没有代码护栏和适用的有效授权/审批。
- 未知执行状态下自动重复副作用调用。
- 敏感数据被无边界传入模型、日志或长期记忆。
- 多个 Agent 并发写权威状态且没有冲突控制。
- 系统能对外声称成功，却没有验证业务结果。

## 发布结论

- **可发布**：关键路径和高风险失败路径有证据验证，剩余风险可接受且有监控。
- **有限试运行**：核心价值成立，但样本、恢复或运营证据不足；限定用户、权限、流量和退出条件。
- **阻断**：存在可能造成严重损失或无法恢复、追责的漏洞，先完成指定修正。

结论必须列出已验证、未验证、剩余风险和下一次复核条件。
