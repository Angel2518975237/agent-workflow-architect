# 证据、结果合并与验收

这是产品展示、Agent 交接与架构审查共用的语义。不要在不同模块分别定义“事实”或“完成”。

## 分开事实、决定和行动建议

- **业务决定**：有权用户选择的目标、范围、政策与取舍，记录决定者和版本。用户说“以三家竞品为范围”是决定；说“市场增长了三倍”仍是待核实陈述。
- **事实性主张**：按下表记录证据与验证状态。工具返回是证据，但其来源、时效、含义和适用范围仍需判断。
- **行动建议**：提出下一步及其依据、风险和前提。建议不是事实，也不授予执行权限。
- **待验证问题 / 待决定问题**：分别交给检查或实验、相应责任人的取舍；不要把可查明的问题都变成人工批准。

| 主张状态 | 含义 | 对流程的影响 |
|---|---|---|
| 假设 | 为推进调查暂时采用的前提 | 可推动授权范围内的低风险调查，不作为关键写入的已确认前提 |
| 候选结论 | 当前证据支持，但未达到验收条件 | 补证、测试或审查；不能靠换个 Agent 复述升级为事实 |
| 已验证 | 在指定版本、时间和范围内有合格证据 | 可作为下游依据，仍需业务规则与授权校验 |
| 冲突待解 | 可比主张互不相容或关键证据矛盾 | 保留双方依据，阻断依赖该主张的关键动作 |
| 已否决 | 证据或明确判定标准推翻了主张 | 保留原因和重新考虑所需条件，不参与事实聚合 |
| 已失效 | 输入更新、来源过期或上游被推翻 | 重新验证受影响部分；不等于该结论在原条件下为假 |

界面可将“已验证”显示为“已确认事实”，但应能展开验证范围与时间。用户的内容偏好否决与证据否决分开记录。未经校准的置信度不是证据强度，也不是执行门槛。

## 最小追溯结构

重要结论关联：主张标识与内容、提出者、状态、适用对象与时间、输入版本、证据引用、验证方法与结果、异议与处理、依赖及替代关系。证据引用定位到原始文档片段、数据记录、日志或工具请求结果，记录来源、采集时间及可用版本。

展示路径：最终结论 → 支持它的子结论 → 验证记录与证据 → 可访问的原始材料。用户默认看简明依据，按需展开。来源无权限、链接失效或材料不完整时如实提示；审计元数据与脱敏摘要不应成为泄露源数据的旁路。

优先引用或受控快照，不无边界复制原文。按业务保留期、访问权限和删除规则管理证据；“可追溯”不要求保存所有聊天或内部推理。

## 合并前先确认是否可比

1. 对齐对象、定义、单位、数据版本和观察时间。旧数据与新数据可能反映变化，不能简单投票选真。
2. 区分同一来源的重复转述、独立支持、可比冲突和无关观点。多个 Agent 引用一个错误来源不增加可靠性。
3. 按来源适用性、直接程度、时效和可复现验证比较证据，不按文风、模型自评或人数排序。
4. 能用原始数据或测试解决的冲突，先做有预算的验证；无法解决则保留未知。只有价值取舍、范围选择或需承担风险的决定交给用户。
5. 只把满足验收要求的内容写成已确认结论；其他内容可在假设、争议或限制中展示。合并后的新主张和新增依赖重新验收，不能继承各片段的通过状态。

异议附在相关候选旁，并记录处理结果；失败路线的保存与迭代控制见 [多 Agent 协作](multi-agent-coordination.md)。

## 在开始前定义完成

每项必要产物定义：覆盖范围、可观察的通过条件、检查方式与证据、验收责任方、关键失败/阻断条件。用户接受是否属于完成条件由业务决定；普通低风险结果不默认增加人工确认或 Reviewer。

分别判断：产物是否通过质量验收、外部动作是否真实完成、业务目标是否达成。报告存在不等于引用有效；请求已接收不等于发布成功；用户点击认可不替代测试。高风险动作需要合格事实前提、业务规则、有效授权同时成立。

验收结果关联当前产物与输入版本，记录通过、退回或无法判断及未满足项。不能把“因预算耗尽停止”标成已完成，也不能为提高通过率在运行中静默降低标准。

例：竞品报告可约定覆盖指定对象、资料时间范围、关键结论可追溯、事实与判断分离；是否需要用户接受和独立审查按用途决定。发布任务可约定目标版本、测试结果、目标环境与业务健康信号，单独记录行动审批而不把它当作发布验收。
