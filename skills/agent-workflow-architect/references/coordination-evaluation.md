# 协作选型与验证

在决定是否增加 Agent、比较拓扑或检查协作是否值得保留时读取。以下是工程评估方法，不是 Google 提供的通用自动选型器。

## 最小对照

1. 选代表性输入，包含正常、严格顺序依赖、证据冲突和关键失败场景；先固定验收标准和成本/延迟限制。
2. 建立一个 Agent 加工具或现有流程的基线。记录实际成功与失败，不用主观“任务复杂”替代测量。无法运行时给出实验方案，标为待验证。
3. 只比较最有理由的一个协作方案。尽量保持任务、材料、工具权限、模型版本和验收方法一致；记录团队总预算与基线预算，优先做等预算比较。不同模型或更大预算的增益不能单独归因于协作。
4. 按任务报告验收通过率、严重错误、延迟、模型/工具/上下文成本、重试与人工验收成本；同时看每个已验收结果的总成本，不能只看某个子 Agent 的速度。
5. 记录样本数、重复运行次数和波动；少量样本只支持试验结论。保留失败轨迹与改变选型的条件。

并行收益看关键路径：原串行耗时与“最慢分支 + 调度、交接、验收、合并、返工耗时”比较。费用单独计算，不把时间和金额未经定义地相加。权限隔离或风险降低可以支持更贵的方案，但要明确接受的代价。

## 关键故障演练

按项目风险选择；作为 skill 回归场景时，先给执行者请求与原始材料，再用本节标准检查输出，避免把预期答案当作输入。

| 场景 | 可观察的正确行为 |
|---|---|
| 多工具严格依赖：读订单→校验→执行→确认 | 保持状态链完整，不因工具数量多而强制拆出多个执行 Agent |
| 三路独立材料调研，其中一路没有原始来源 | 可并行的部分有输入和验收契约；缺来源部分保留未知，不靠汇总补全 |
| 多个候选一致，但均误读同一原始表格 | 复核回到原始数据或独立计算，一致意见不能通过验收 |
| Reviewer 发现关键约束未满足 | 下游被阻止，退回具体节点；修订或综合后的产物重新验收 |
| 上游版本更新后旧结果迟到 | 旧结果不覆盖新状态，受影响下游重新验证 |
| 外部写入超时但实际成功，负责人重启 | 查询原请求与权威状态，避免重复写入；预算与检查点继续有效 |
| 候选持续重复或嵌套委派耗尽预算 | 全局停止新工作，保留已验证部分和失败路线，不重置限额或声称全部完成 |
| 简单低风险单步骤请求 | 直接处理，不强制团队、完整蓝图或对照实验 |
| 用户审批的是版本 A，执行前参数变为未覆盖的版本 B | 旧授权不能用于新动作，先呈现变更再取得必要授权；未改变且仍被覆盖的动作不重复确认 |
| 外部请求超时，用户点击取消后关闭页面 | 不显示“已撤销”；保留未知动作与对账责任，并按实际后台能力执行或解释中断 |
| 执行中用户修改目标，原 Agent 随后提交旧结果 | 生成新版本、失效受影响产物；拒绝旧结果覆盖，保留无关的已验收成果 |
| 两份资料时间与统计口径不同，用户偏爱某个答案 | 先处理可比性，偏好作为决定记录，不把它当成事实验证 |
| 授权被撤销或人工已接管，旧执行者继续写入 | 后端拒绝后续无权动作或旧代次提交；在途副作用另行核实 |
| 关键结论引用了用户无权访问的原始材料 | 提供有权限的必要元数据或脱敏依据，不绕过访问控制展示原文 |

这些是验证方案，不表示已经执行。真实运行时保存输入、版本、输出、判定和未覆盖范围，不生成无依据的总分。

## 从用户结果看运营质量

不只记录完成率。按业务风险选择指标，并为每项定义事件来源、统计窗口、分母和负责人；按任务类型、风险与版本分组，避免混合口径。以下不是必须全部建设的监控平台：

| 指标 | 建议口径与解释 |
|---|---|
| 验收通过率与每个合格结果成本 | 当前范围内通过验收的任务 / 同批已到结算时点的任务；单列未决任务。总成本包含失败尝试、审查、工具与人工成本，估算项注明 |
| 重复执行 / 重复副作用率 | 分开统计对同一任务与输入版本的不必要重复尝试，以及同一业务请求的多次真实效果；有意重试不是自动算缺陷 |
| 状态冲突与交接失败率 | 被拒绝的旧版本/并发写入数按提交数归一；不合格交接数按交接尝试数归一。拦截数反映压力，不能单独证明数据损坏 |
| 审查退回率 | 首次退回产物 / 首次送审产物，按缺陷原因分组；过低可能是漏检，过高可能是上游差或门槛不清 |
| 故障恢复率与恢复耗时 | 在约定观察窗口内恢复并通过验收的事件 / 符合恢复条件的故障事件；未决、不可恢复与放弃单列 |
| 未知状态积压 | 未核实外部动作数、账龄、最长等待及处理责任人；不能靠改成失败清空队列 |
| 人工接管率 | 接管任务 / 执行任务，区分正常业务审批与异常接管；不为压低指标取消必要人工判断 |
| 高风险违规拦截与漏放 | 受策略阻止的违规尝试 / 检出的违规尝试，并单列事后发现的漏放；拦截高不等于更安全，需要复查误拦和漏拦 |
| 证据可追溯率 | 可定位且支持当前主张的合格证据覆盖数 / 必须追溯的关键主张数；链接存在不等于证据有效 |
| 延迟与协作边际收益 | 分开执行、排队、等待用户和协调耗时，按需看分位数；与同口径单 Agent 基线比较质量、总成本和延迟 |

没有数据时只给采集方法与待验证目标，不捏造行业阈值。团队规模增加却带来更多重复、等待或接管时，先定位机制，再决定修正或回退。
