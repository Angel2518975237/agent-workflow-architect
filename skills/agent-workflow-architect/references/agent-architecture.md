# Agent 架构判断

架构目标是用最少的不确定性解决业务问题，而不是最大化 Agent 数量。

## 决策阶梯

按顺序判断：

1. **确定性代码能否更可靠地解决？** 校验、计算、过滤、权限和状态更新通常应该写成程序。
2. **是否真的需要模型判断？** 模糊语言理解、非结构化信息提取、候选方案生成和带依据的权衡可能适合 Agent。
3. **一个 Agent 加工具是否足够？** 如果目标统一、步骤严格依赖前序状态，优先保持完整上下文；工具多也不自动意味着需要拆分。
4. **多 Agent 的专业隔离或并行收益是否大于协调成本？** 只有答案为是才增加 Agent。
5. **哪些决定必须由真人承担？** 资金、法律承诺、敏感权限、例外政策和不可逆动作通常需要审批或明确授权。

## 单 Agent 与多 Agent

优先单 Agent，当：

- 任务共享一套上下文和成功标准。
- 工具调用链紧密相连，拆分会反复复制上下文或同步中间状态。
- 不需要权限隔离或独立复核。
- 延迟、费用或调试难度敏感。

考虑多 Agent，当：

- 专业任务能清晰分开，输入输出契约稳定。
- 独立任务可以真正并行。
- 高风险结果需要与实现者分离的审查者。
- 不同 Agent 必须拥有不同权限或数据视图。

不要用多 Agent 修复一个定义不清的目标。模糊任务分给更多 Agent 只会产生更多互相矛盾的答案。

## 责任边界

为每个 Agent 明确：

- 单一职责和明确目标。
- 所需最小上下文。
- 可以读取和写入的资源。
- 可调用工具及其风险等级。
- 结构化输入、输出、禁止事项和拒绝条件。
- 能否调整计划，调整的范围与受影响产物的失效规则。
- 成功标准、超时和升级路径。

Agent 不应自己扩大目标、增加权限或把未确认推断写成事实。

## 状态所有权

每一类业务状态只能有一个权威来源和一个明确写入责任方。区分：

- **会话上下文**：只为当前交互服务，不等于长期事实。
- **工作流状态**：当前步骤、已完成动作、待审批和恢复信息。
- **业务系统状态**：订单、客户、资金等权威记录。
- **长期记忆**：经过筛选、可修正、有来源和生命周期的知识。

不要让自由文本聊天记录成为生产状态。跨 Agent 传递结构化摘要和证据引用，而不是默认转发全部历史。

## 关键约束落点

以下约束不能只写在 Prompt：

- 权限和资源范围。
- 必填字段、数值范围和格式。
- 必须调用的验证工具。
- 幂等、并发和唯一性。
- 审批门槛与不可逆操作。
- 最大轮次、费用和重试次数。

Prompt 负责意图和判断指导；代码、模式校验、数据库约束和工具护栏负责强制执行。

## 模型不确定性

模型给出的“置信度”只有经过代表性数据校准后才有业务意义。更可靠的做法是：

- 要求证据来源和可验证字段。
- 对关键输出使用结构化模式校验。
- 将低证据、矛盾或超范围结果路由到人工。
- 用真实失败样例测试，而不是依赖模型自评。

## 推荐产物

架构设计至少说明：业务目标、Agent/代码/真人边界、状态所有权、数据流、工具权限、主要失败路径、人工介入点和最小验证方案。

## 按信息流选择拓扑

以下是选型起点，最终用代表性任务验证，不用角色名称代替控制关系。

| 拓扑 | 适合的任务条件 | 主要代价与拦截位置 |
|---|---|---|
| Single-Agent：一个 Agent 保持完整上下文 | 严格串行、状态紧耦合，或基线已满足目标 | 单点判断可能出错；由工具校验、测试或必要的独立复核拦截 |
| Independent：各自执行，末端聚合 | 输入独立、子结果可单独验收 | 中途缺少互查；每个结果必须先验收再参与聚合 |
| Centralized：负责人调度与验收 | 需要统一状态、跨子任务整合 | 负责人可能拥塞或带入共同偏见；保留原始证据和独立验收通道 |
| Decentralized：直接交换证据和质疑 | 确有点对点协商收益 | 通信和回放复杂；限定消息轮次、状态写入者和最终裁决规则 |
| Hybrid：集中控制加局部直接协作 | 少数局部问题需要相互质疑 | 明确局部讨论边界，统一预算和最终验收，避免双重指挥 |

需要多 Agent 且无相反证据时，可从集中式小团队开始。不要强迫去中心化方案设置全局唯一调度者，但每项产物、争议和权限都必须有明确归属。

分开描述三个层次：拓扑决定信息和控制如何流动；协作模式决定候选、质疑、验收和修订如何推进；角色只决定当前谁负责。一个 Reviewer 角色并不自动构成有效的审查控制路径。

记录选定方案、排除其他方案的原因、待验证假设和回退条件。实测比较见 [协作评估](coordination-evaluation.md)。
